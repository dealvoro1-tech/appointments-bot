# Бот для керування записами клієнтів (Telegram)

Приватний Telegram-бот для одного власника (або кількох довірених осіб зі списку доступу).
Увесь інтерфейс — **українською**: меню, кнопки, помилки валідації, нагадування.
Часовий пояс — **Europe/Kyiv**. Ціни — у гривнях (`500 грн`).

## Чому такий стек

* **Python 3.10+ і лише стандартна бібліотека** (urllib, sqlite3, zoneinfo, threading) — немає залежностей,
  які треба оновлювати, і бота легко перенести на будь-який комп’ютер чи сервер.
  Єдина залежність `tzdata` потрібна лише на Windows.
* **SQLite** — один файл бази, достатньо для одного власника, записи переживають перезапуск.
* Опитування (`getUpdates`), а не вебхуки: не потрібні домен, HTTPS чи відкриті порти.

## Можливості

* **Новий запис**: рік → місяць → день (інлайн-кнопки), швидкі «Сьогодні»/«Завтра», потім час, процедура,
  клієнт, ціна. Час, процедуру й клієнта можна обрати кнопками (частіші значення та вільні години),
  ціна підказується з останнього запису цієї процедури. Перед збереженням — екран підтвердження.
  Телефон і нотатки — необов’язкові, додаються кнопками на екрані підтвердження.
* **Календар**: перегляд за роками/місяцями/днями. У місяці — сітка з заголовком `пн вт ср чт пт сб нд`;
  кнопка «Списком із днями тижня» показує кожну дату з її днем тижня (`12 чт`). Дні із записами позначено `•`,
  сьогодні — `[7]`. Записи дня — у хронологічному порядку, з підсумком.
* **Дохід за місяцями**: перегляд суми цін активних записів за кожен місяць та рік; скасовані записи
  не враховуються. Це сума за цінами записів, а не облік отриманих оплат.
* **Запис**: повні деталі, редагування будь-якого поля (включно з перенесенням на іншу дату через календар),
  скасування з підтвердженням (запис лишається в базі зі статусом «скасовано»).
* **Дублі**: якщо на цю дату й годину вже є запис — бот попереджає й питає, чи продовжувати.
  Перевірка є і під час введення часу, і повторно перед збереженням.
* **Нагадування**: вмикаються/вимикаються в меню; за замовчуванням за 24 год, пресети 1/2/12/24/48 год або
  власне значення 1–168 год. Нагадування приходить один раз; при перенесенні запису скидається.
* **Відновлення**: стан діалогу зберігається в БД. Після перезапуску чи «Головного меню» посеред створення
  запису з’явиться кнопка «▶️ Продовжити незавершений запис». Наявні записи ніколи не зачіпаються.
* **Доступ**: лише користувачі зі списку `ALLOWED_USER_IDS`; усі інші отримують «Доступ заборонено».
  Працює тільки в приватних чатах.

## Швидкий старт

1. Створіть бота в [@BotFather](https://t.me/BotFather) (`/newbot`) і скопіюйте токен.
2. Дізнайтеся свій числовий Telegram ID, наприклад у [@userinfobot](https://t.me/userinfobot).
3. Встановіть Python 3.10+ і підготуйте проєкт.

**Windows (PowerShell):**
```powershell
cd appointments-bot
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
notepad .env        # впишіть BOT_TOKEN та ALLOWED_USER_IDS
python -m appbot
```

**macOS / Linux:**
```bash
cd appointments-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env && nano .env     # впишіть BOT_TOKEN та ALLOWED_USER_IDS
python -m appbot
```

На macOS бот автоматично використовує системний файл сертифікатів `/etc/ssl/cert.pem`, якщо він доступний.
Якщо потрібно вказати інший довірений CA-файл, задайте `SSL_CERT_FILE` перед запуском.

Відкрийте бота в Telegram і натисніть `/start`. Зупинка — `Ctrl+C`.

> Важливо: бот має **один працюючий екземпляр** на токен. Якщо запустите двічі, Telegram поверне помилку
> конфлікту `getUpdates`.

## Налаштування (`.env`)

| Змінна | Обов’язкова | За замовчуванням | Опис |
|---|---|---|---|
| `BOT_TOKEN` | так | — | токен від @BotFather |
| `ALLOWED_USER_IDS` | так | — | ID власника (кілька — через кому). Порожній список = бот не запуститься |
| `DATABASE_PATH` | ні | `data/appointments.db` | файл SQLite |
| `DEFAULT_REMINDER_HOURS` | ні | `24` | початкове значення часу нагадування (1–168) |
| `REMINDER_CHECK_SECONDS` | ні | `30` | як часто перевіряти нагадування |
| `LOG_LEVEL` | ні | `INFO` | `DEBUG`/`INFO`/`WARNING`/`ERROR` |

Токен лише в змінних оточення/`.env` (файл у `.gitignore`). У коді токенів немає.

## База даних

Ініціалізація автоматична: при кожному старті `init_schema()` створює таблиці, якщо їх немає, і не чіпає
наявні дані (версія схеми — `PRAGMA user_version`). Таблиці: `appointments`, `settings`, `sessions`.
Резервна копія — просто скопіюйте файл `data/appointments.db` (бажано, коли бот зупинено).

Усі години зберігаються як київські `HH:MM` плюс UTC-мітка `starts_at`; час створення — UTC (показується
в Києві). Ціни — в копійках (цілі числа), без похибок округлення.

## Тести

```bash
python -m unittest discover -s tests -t . -v
```

Тести не потребують мережі чи токена: Telegram підміняється, БД — тимчасовий файл. Покрито: валідацію,
дати/дні тижня/Київ та перехід на літній час, минулі дати й час, дублі, збереження після «перезапуску»,
повні сценарії діалогу, скасування, редагування, нагадування, доступ, екранування HTML.

## Розгортання

### GitHub та Veltramon

Створіть на GitHub **порожній приватний репозиторій** (без README, ліцензії та `.gitignore`), потім виконайте
команди з папки проєкту. Замініть `ВАШ_ЛОГІН` на свій GitHub username:

```bash
cd ~/Desktop/appointments-bot
git init -b main
git check-ignore -v .env data/appointments.db .venv
git add .
git status --short
git commit -m "Initial appointments bot"
git remote add origin https://github.com/ВАШ_ЛОГІН/appointments-bot.git
git push -u origin main
```

Перед `git commit` перевірте `git status`: файлів `.env`, `data/appointments.db` та `.venv` там бути не повинно.
`.env.example` можна комітити — він містить лише шаблонні значення.

У Veltramon вставте URL приватного репозиторію та надайте платформі доступ до нього. Додайте у налаштуваннях
сервера секретні змінні `BOT_TOKEN` і `ALLOWED_USER_IDS`; `.env` туди з Git не передається. Команда запуску:
`python -m appbot` (залежності беруться з `requirements.txt`). Для збереження записів після перезапуску налаштуйте
постійне сховище для `data/appointments.db` і встановіть `DATABASE_PATH` у шлях на цьому сховищі.

* **Постійно на комп’ютері/сервері**: бот працює, лише поки запущений процес. Нагадування надсилаються
  тільки коли бот онлайн (пропущені під час простою надішлються після старту, якщо запис ще не почався).
* **Linux + systemd**: див. `deploy/appbot.service` (поправте шляхи й користувача), далі
  `systemctl enable --now appbot`. Логи: `journalctl -u appbot -f`.
* **Docker**:
  ```bash
  docker build -t appbot .
  docker run -d --name appbot --restart unless-stopped --env-file .env -v appbot-data:/app/data appbot
  ```
* **Windows**: для автозапуску можна створити завдання в «Планувальнику завдань» з командою
  `.venv\Scripts\python.exe -m appbot` і робочою папкою проєкту.
* **Veltramon**: підключіть Git-репозиторій, додайте змінні `BOT_TOKEN` і `ALLOWED_USER_IDS` у налаштуваннях
  сервера, а командою запуску вкажіть `python -m appbot`. Збережіть `data/appointments.db` на постійному
  сховищі платформи та вмикайте резервні копії, щоб не втратити записи після перевстановлення.

## Приватність і логи

У логах немає тексту повідомлень, імен, телефонів, цін, нотаток і токена — лише службові події
(ID користувача при відмові в доступі, тип помилки та місце в коді, номер запису для збоїв нагадувань).

## Припущення

* Один календар на всіх користувачів зі списку доступу; нагадування отримують усі вони.
* «Дубль» — це збіг дати **та** години (тривалість процедур не відстежується).
* Телефон нормалізується до `+380XXXXXXXXX` для українських номерів; міжнародні номери з `+` теж приймаються.
* Ціна 0 дозволена (безкоштовна консультація); максимум — 1 000 000 грн.
* Новий запис можна створити на сьогодні (якщо час ще не минув) і на 2 роки вперед через вибір року.
* Скасовані записи не показуються в календарі й не блокують час, але зберігаються в базі.

tests/            unittest
deploy/           systemd-юніт
